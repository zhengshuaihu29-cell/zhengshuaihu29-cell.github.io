Memo Reminder

记事提醒
A bilingual reminder app that survives Android's battery savers.
一款能在系统省电策略下稳定工作的双语记事提醒应用。
RoleSolo developer — design, code, release
PlatformAndroid  ·  Kotlin
TypeUtility / Productivity

Memo Reminder is a native Android reminder app written in Kotlin. Users create one-off or daily repeating reminders with a title, date and time, then manage everything from a single list — pause, snooze for 30 minutes, or delete without ever opening a detail screen.

记事提醒是一款使用 Kotlin 开发的原生 Android 提醒应用。用户可创建一次性或每日重复的提醒， 填写事件名称、日期与时间，并在同一个列表中完成暂停、延迟 30 分钟或删除，无需进入详情页。

The hard part of a reminder app is not the UI — it is making sure the alarm actually fires. The app uses exact alarms via AlarmManager (setExactAndAllowWhileIdle) so reminders cut through Doze mode, a BootReceiver that rebuilds every pending reminder after a reboot, and an in-app “Background settings” guide that walks users through autostart and battery-optimisation permissions — the practical fix for OEM task-killers on Chinese Android skins.

提醒类应用真正的难点不在界面，而在于“闹钟是否真的会响”。应用通过 AlarmManager 的精确闹钟（setExactAndAllowWhileIdle）让提醒能够穿透 Doze 休眠； 通过 BootReceiver 在设备重启后自动重建全部待触发提醒；并内置「后台运行设置」引导页， 带领用户开启自启动、关闭省电限制——这正是解决国产 Android 系统杀后台的实用方案。

Key features

  • Create, pause, snooze (+30 min) and delete from one list screen
  • Two reminder modes: countdown and fixed-time
  • Daily repeat with next-occurrence preview
  • Exact alarms that cut through Doze mode
  • Pending alarms automatically restored after device reboot
  • Runtime English / 简体中文 switch
  • In-app guide for autostart & battery-optimisation settings
  • Material date & time pickers, snackbar confirmations

核心功能

  • 单一列表内即可创建、暂停、延迟（+30 分钟）与删除
  • 两种提醒方式：倒计时与定时
  • 每日重复，并显示下次触发时间
  • 精确闹钟，可穿透 Doze 休眠
  • 设备重启后自动恢复全部待触发提醒
  • 运行时中英文一键切换
  • 内置自启动与省电策略设置引导
  • Material 日期/时间选择器与操作反馈提示
Tech Kotlin · Android SDK · AlarmManager · NotificationManager · BroadcastReceiver · Foreground Service · SharedPreferences · Material Components · Gradle

Splash Paint Blend

泼彩混色
A real-time fluid painting game with no engine behind it.
一款不使用任何游戏引擎、纯手写渲染的流体泼色游戏。
RoleSolo developer — design, code, release
PlatformAndroid  ·  Kotlin
TypeCasual / Arcade

Splash Paint Blend is a casual arcade game for Android, rendered entirely with a custom View and the Android Canvas API — no Unity, no third-party engine. Every frame is driven by a Choreographer loop, and blobs are drawn with radial gradients and blend modes, so wet paint spreads, mixes and bleeds into its neighbours in real time.

泼彩混色是一款 Android 休闲街机游戏，画面完全由自定义 View 与 Android Canvas API 手写渲染，不依赖 Unity 或任何第三方引擎。每一帧由 Choreographer 驱动，色块使用径向渐变与混合模式绘制， 让颜料像真实湿颜料一样实时扩散、交融、晕染。

Tap anywhere to splash ink; hold to switch colours. Each target is a labelled colour blob — Saffron, Viridian, Crimson — ringed by a timer that depletes as you watch. Cover it with a close enough hue before the ring closes and you score; the tighter the colour match, the higher the points.

点击屏幕任意位置泼洒颜料，长按切换颜色。每个目标是带有名称的色斑——藏红花黄、翠绿、绯红， 外圈有一道随时间流逝的计时环。在计时环消失前用足够接近的颜色覆盖它即可得分；颜色匹配得越准，分数越高。

Key features

  • Custom real-time renderer: radial gradients + blend modes
  • Choreographer-driven frame loop for smooth animation
  • Tap to splash, hold to switch ink colour
  • Timed target rings with colour-similarity scoring
  • Lives, live score and best-score tracking
  • Pause, clear-canvas and full game-over flow
  • No engine overhead — small APK, smooth on low-end devices

核心功能

  • 自研实时渲染：径向渐变 + 混合模式
  • Choreographer 驱动帧循环，动画流畅
  • 点击泼色，长按切换墨色
  • 计时目标环 + 颜色相似度评分
  • 生命值、实时分数与最高分记录
  • 暂停、清空画布与完整结算流程
  • 无需引擎、包体小，低端机型同样流畅
Tech Kotlin · Custom View & Canvas · Choreographer frame loop · RadialGradient · BlendMode compositing · Android SDK

Google Play Publishing

Google Play 上架发布
Dozens of titles shipped end to end.
数十款应用的完整上架经验。

I have taken dozens of Android Studio mini-games through the complete Google Play release pipeline for my company — end to end, not just the build. That includes generating signed release APKs/AABs and managing signing keys, preparing store listing assets (app icon, feature graphic, screenshots, short and long descriptions), completing content rating and policy declarations, and pushing each release through Play Console review.

我曾为公司把数十款 Android Studio 小游戏完整走完 Google Play 上架流程—— 不只是打包，而是全流程：生成签名 Release APK/AAB 并管理签名密钥、准备商店素材（应用图标、宣传图、截图、 长短描述）、完成内容分级与政策声明，并提交 Play Console 审核发布。

At that volume the process becomes repeatable: build → sign → assemble store assets → submit → verify on-device. Having done it dozens of times means I know where submissions get rejected, and how to avoid it.

在批量交付的项目中，这套流程被标准化并可复现：构建 → 签名 → 整理商店素材 → 提交 → 真机验证。做过数十次，意味着我清楚哪些环节容易被打回，以及如何提前规避。
